System design

Keep judgment, arithmetic and authority explicit.

Optional model components propose opportunities and narrative. Typed tools own facts and calculations. PostgreSQL stores durable state, and a separate approval API owns human decisions.

Source evidence→Scoped MCP tools→Deterministic sizing→Human approval→KPI monitoring

Grounded numbers

Server-issued quantity references bind metric, units, company, period and evidence. Numeric validation applies to both proposals and narrative.

Durable decisions

Checkpoints, claims and idempotency support recovery. Approval and rejection are audited. Model-callable tools cannot approve a plan.

Company boundaries

Request scope and PostgreSQL row-level security enforce tenant access. Value claims resolve to stored evidence or the workflow pauses.

Scope and acceptance

Evidence with clear boundaries.

  • All showcased companies, evidence and financial results are synthetic.
  • The default demo uses rules. Current live-model acceptance is a separate, budgeted gate.
  • Core application/database image scans pass. Optional observability images retain documented findings.
  • Human MCP/browser acceptance, real-source reconciliation and production reviews remain separate obligations.
This project demonstrates AI-assisted engineering with inspectable implementation and reproducible checks. Automated checks are not represented as independent human review.
