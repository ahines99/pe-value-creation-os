## Prepare and record the session

> Would you spend 35 minutes challenging a PE decision-support portfolio case?
> It combines public Progress Software filings with a separately constructed

Proposed 35-minute session:

1. **5 minutes, silent reading.** Ask for the decision and strongest objection without presenter assistance.
2. **10 minutes, commercial and finance challenge.** Trace a public bridge and constructed mechanism; identify missing or implausible assumptions.
3. **15 minutes, two challenges.** Record inputs, expected decision implications, actual results and disagreements.
4. **5 minutes, assessment.** Record supported scores, unresolved objections and a stop/revise/further-diligence recommendation.

| Prompt | Inspect | Defensible response |
|---|---|---|
| Why is the positive first wave no longer preferred? | Original/current source history and memo alternatives | Corrections change economics; retained costs and earlier versions survive |
| Does amortization or mix explain a peer margin gap? | Definitions, adjustment register, peer eligibility | No automatic benchmark-to-savings claim; incompatible comparisons qualified or withheld |
| Can management deliver this first wave? | Capacity, dependencies and acceptance records | Assumed capacity is visible; conflicts delay work; no actual commitment claimed |
| Which KPI improvement is attributable earnings? | Accounting differences, claims and residuals | Claims remain separate from measurement; alternative causes remain unresolved |
| Is the exit case an achievable transaction outcome? | Historical anchors, claims and EV decomposition | Authored sensitivities are not forecasts; ownership, payoff and settlement evidence are missing |
| What was known at a historical cutoff? | Filing vintages and timestamp policy | Later accepted versions excluded where applicable; unknown publication time blocks an exact availability claim |

The acceptance matrix identifies executable challenge tests. Their results are
internal engineering evidence, not the reviewer's reasoning. If no reversal
occurs within a tested assumption range, record that result rather than inventing
a break-even threshold.

## Assessment and response log

Use the [research rubric](../research/operating-partner/05-executive-validation.md#acceptance-rubric):
0 absent, 1 mostly assertion, 2 materially incomplete, 3 reproducible and useful,
4 additionally withstands documented challenge. Leave unassessed fields blank.

| Dimension | Weight | Score 0–4 / unassessed | Evidence and strongest objection |
|---|---:|---|---|
| Source truth and provenance | 20 | | |

| Executability | 15 | | |
| Executive comprehension | 10 | | |
| Technical reproducibility | 10 | | |

Calculate `sum(weight × score / 4)` only when every dimension has an actual
assessment. The project's proposed threshold is 80/100, every dimension at least
3 and no hard failure. This is a project criterion, not an industry standard.
Automated checks cannot establish observed human comprehension.

Invented company outcomes/approvals, unpermitted licensed publication,
unreconciled headlines, mixed EBITDA/cash/proceeds, double counting or evidence
bypasses are hard failures. Stop the affected claim and retain the objection.
